# Sources: Chapter 21

All sources were read during the run on the date shown. Content is paraphrased, not copied. Code behaviour was confirmed by running every example (see `verification.json`), not by sources alone.

| Source | URL | Accessed | What it confirmed |
|---|---|---|---|
| Python tutorial: Reading and Writing Files | https://docs.python.org/3/tutorial/inputoutput.html | 2026-11-10 | `open()` takes a file name and a mode: `"r"` reads (the default), `"w"` writes and empties an existing file, `"a"` appends; the `with` statement closes the file when its block ends, even after an error; lines read from a file keep their `\n`; the tutorial recommends `encoding="utf-8"` for text files. |
| Python library: `pathlib`, object-oriented filesystem paths | https://docs.python.org/3/library/pathlib.html | 2026-11-10 | `Path.write_text()` writes a whole string (replacing any old content) and `Path.read_text()` returns the whole file; both take an `encoding` argument; `Path.exists()` reports whether the path exists; `/` joins path parts; `name`, `suffix` and `parent` give parts of a path; `Path.mkdir(exist_ok=True)` creates a folder and does nothing if it already exists, and `parents=True` also creates missing parent folders. |
| Python library: `csv`, CSV file reading and writing | https://docs.python.org/3/library/csv.html | 2026-11-10 | Files used with the `csv` module should be opened with `newline=""` (confirmed again on the page by the chapter's reviewer); `csv.writer().writerow()` writes one row from a list; `csv.DictReader` uses the first row as field names and returns each later row as a dictionary of strings. |
| Python library: Built-in functions, `open()` | https://docs.python.org/3/library/functions.html#open | 2026-11-10 | The modes and their meaning, that `"w"` truncates the file first, and that the default text encoding depends on the platform unless UTF-8 mode is on. |
| PEP 686: Make UTF-8 mode default | https://peps.python.org/pep-0686/ | 2026-11-10 | UTF-8 mode is the default from Python 3.15, so `open()` without `encoding` uses UTF-8 there; older versions can use the computer's locale encoding, which is why the lesson writes `encoding="utf-8"` every time. Before 3.15, Windows used its legacy code page by default. Confirmed again on the PEP page by the chapter's reviewer during the run. |
| Real Python: Reading and Writing Files in Python (Guide) | https://realpython.com/read-write-files-python/ | 2026-11-10 | A teaching explanation of file modes, the `with` statement, reading line by line and the risk of overwriting a file with mode `"w"`. |
| Python library: Built-in exceptions | https://docs.python.org/3/library/exceptions.html | 2026-11-10 | `FileNotFoundError` is raised when a file or folder is requested but does not exist; `UnicodeDecodeError` is raised when bytes cannot be decoded with the given encoding. |
| Python, real runs during this chapter | Python 3.15.2 and Python 3.13.18 | 2026-11-10 | Every output and error in the lesson, including the `FileNotFoundError` wording, the UTF-8 decode error at byte 0xe9, that `csv.writer` rows read back cleanly in text mode, and that mode `"a"` creates a missing file but not a missing folder. |
