## What was built
- **Story:** Asha's oldest function, `close_day()`, adds tax, prints a line and changes a global week total, all at once. The mission is the day report redesigned: pass values in, return results out, a default tax rate and a keyword argument.
- **Lesson steps:**
  1. a local variable used outside its function (`NameError`);
  2. a function that reads a global at call time (the hidden link);
  3. assigning to a global name inside a function (`UnboundLocalError`), and the pass-in, return-out fix;
  4. default arguments, and that a default is created once;
  5. positional and keyword arguments;
  6. one job per function, tested with one comparison.
- **Work with AI:** all six stages work on splitting `close_day()`.
  - **Plan:** the AI lists the function's three jobs, with line numbers.
  - **Write:** Asha writes `day_total()` herself first, the AI predicts it, and she saves the original program's output as her target.
  - **Generate:** the AI pair moment. The AI's `report_line()` prints instead of returning, so two extra lines say `None`, although it promised the same output.
  - **Test:** the AI's three cases with exact expected lines, run on its first version (all FAIL) and on the fixed version (all pass).
  - **Debug:** an `UnboundLocalError` in `add_to_week()`. The AI's first fix uses `global`, which breaks Asha's rule, so she asks for one that passes the week total in and returns it. The final split (`ai_split_final.py`) matches the target and passes all three cases.
  - **Improve:** the AI suggests a list default, `sales=[]`. A test with two days shows Tuesday's sale in Monday's list, so Asha rejects it.
- **Common mistakes:** a local name used outside (`NameError`), a positional argument after a keyword argument, a default before a parameter without one (both `SyntaxError`), and a list as a default.
